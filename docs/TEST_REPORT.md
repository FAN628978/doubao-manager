## 自动化验证的范围

- 4 个模式：文生视频、首帧图生视频、首尾帧生视频、多参考图生视频；真实 Chromium 完成模拟控件设置、上传确认、提交、获取视频、容器校验。
- REST API → 异步 Worker → Chromium → MP4 归档端到端（模拟网页）；幂等请求不会重复建单。
- 10 个故障注入情形：缺少模式或时长控件、缺少上传槽、上传未确认、需要验证码、额度用尽、需登录、缺少提交按钮、任务不结束、页面仅有旧视频。
- 安全恢复：重启中断后阻止自动重复提交，禁止普通状态接口伪造成功。
- 视频源域名/重定向限制；无信任来源则停止下载。
- 需人工复查的任务只允许显式确认并上传对应结果，验证文件头和 ?????；保存结果来源 `human_verified_upload`。
- 浏览器脚本语法及 Python 文件编译检查。

**自动化测试结果：24 项通过。**

### 已实际验证

- 项目 Chrome 首次下载、Content-Length/ZIP CRC/版本资源/SHA-256 校验，安装位置为 `browser/chrome/156.0.8078.80/`，未调用或覆盖系统 Chrome。
- 项目 Chrome 使用临时独立 Profile 连续启动两次成功；应用代码仍原样使用 `data/profiles/{account_id}`，安装器未读取、删除、重建或迁移账号 Profile。
- MV3 扩展自动加载，豆包域页面出现 Shadow DOM 面板，Service Worker 正常启动。
- 本地 Mock 后端 + 两个 Mock 豆包标签页：账号 A/job-a 与账号 B/job-b 分别显示正确任务，页面刷新与项目 Chrome 重启后恢复，无串账号、串任务。
- 面板显示五个原流程按钮，并验证其调用现有调度、人工准备、发送、确认语、召回下载和推送接口；禁用条件、成功/失败反馈和确认提示由真实任务状态驱动。
- 关闭面板不关闭标签页、不发送浏览器关闭请求；扩展未参与后台任务执行，扩展关闭不影响 Python Worker。
- 人工接管仅取消当前任务 Worker 并保留绑定页面；同账号其他任务不受影响。提交结果不明确时恢复返回 409，禁止盲目重提。
- 扩展解析接口在启用 `DOUBAO_LOCAL_API_KEY` 后拒绝无 Key 请求，正确 Key 可访问；Key 不进入内容脚本或豆包页面 DOM。
